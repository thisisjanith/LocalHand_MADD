# LocalHand

Hyper-local neighbourhood services and marketplace app. The user drops a pin at
sign-up and everything — Home's "Near You", Search results, and the assistant's
recommendations — is ranked by real distance from it.
Kotlin + Jetpack Compose (Material 3), single Activity, MVVM.

The full product spec lives in `ClaudeCode_PROMPT_LOCALHAND.md` and is the
source of truth for screens, design tokens and behaviour.

## Build

```bash
./gradlew :app:assembleDebug
```

Requires JDK 21. If `java` is not on PATH, Android Studio's bundled JBR works:

```bash
JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew :app:assembleDebug
```

### Toolchain constraints (deliberate — don't "fix" these)

- `android.builtInKotlin=false` and `android.newDsl=false` in `gradle.properties`:
  KSP (which Room's compiler needs) is incompatible with AGP 9's built-in Kotlin,
  and the standalone Kotlin plugin is incompatible with AGP 9's new DSL. Both
  flags can be dropped once KSP supports built-in Kotlin.
- `compileSdk = 37` while `targetSdk = 35`: Compose 1.12 requires compiling
  against API 37. These are independent settings; the spec's targetSdk is 35.

## Architecture

`@Composable` screens → `ViewModel` (`StateFlow`) → repository → Room / DataStore.

- `data/model` — entities and enums exactly as specified in the spec.
- `data/local` — Room database, DAO, type converters, and the twelve seeded listings.
- `data/location` — `LocationProvider` (platform `LocationManager`, no Play Services),
  haversine `distanceMetres`, and `formatDistance`. The user's pin lives in
  DataStore; `rankByDistance` in the repository turns it into an ordering.
- `data/repo` — `ListingRepository` (single source of truth, everything as `Flow`)
  and `PreferencesRepository` (onboarding gate, session flag, dark mode).
- `ui/theme` — **all** colours, dimensions and type styles. Composables must not
  hard-code hex values or sp/dp literals; add a token instead. Note the light
  `background` is the warmer `#FDF7F2` from the Figma exports, deliberately
  overriding the spec table's `#F8F6F2`.
- `ui/components` — shared pieces: bottom nav, cards/rows, fields, badges.
- `ui/screens` — the ten screens.
- `LocalHandNavHost.kt` — routes and the Scaffold hosting the bottom bar.

`LocalHandApp` is a minimal service locator; `LocalHandViewModelFactory` builds
every ViewModel from it.

## Assets

- `res/font/plus_jakarta_sans.ttf` is the upstream variable font; weights are
  selected via the `wght` axis (minSdk 26 supports this).
- Listing artwork in `res/drawable/listing_*.xml` is generated by
  `tools/gen_listing_drawables.py` — edit the script, not the XML. These stand in
  for photos; swap in real images and update `SeedData.kt` when available.

## Not yet done

- The Figma PNGs referenced in the spec were never added to the project, so the
  screens were built from the written spec. Compare against the exports and
  adjust spacing/layout per screen when they land.
- The map pin picker's *surface* is still a `Canvas`-drawn grid (a real map needs
  a Google Maps API key), but the pin is functional: tap/drag moves it and it
  reports real coordinates. Swapping in Google Maps Compose means replacing the
  grid surface and keeping the same `center` / `onPinMoved` contract.
- Seeded listings keep their Malabe coordinates. When testing from elsewhere,
  set the emulator location (`adb emu geo fix <lng> <lat>`) so distances read
  realistically — note a cached fix can take precedence, so repeat it if the
  reverse-geocoded area name looks wrong.
- The photo picker zone is inert; new listings fall back to a category drawable.
